# Sandbox Init

Reset a disposable consumer sandbox to a pristine, verified, launch-ready
state — one deterministic script, not a hand-typed cleanup sequence.

## When to use

- About to start a game-build session in a sandbox
- Previous run died mid-way and the sandbox is dirty
- Suspect a sandbox is broken (drifted submodule, missing ledger)

## Layout the script creates

```
test/<name>/              # fresh consumer git repo (session cwd anchor)
├── AGENTS.md             # generated by bd setup <harness> (managed Beads block)
├── .beads/               # fresh bd ledger (bd init --quiet --stealth)
└── .agents/              # git SUBMODULE -> pipeline-dev repo @ committed HEAD
    ├── skills/           # engine-agnostic game-build skills (genesis, ...)
    ├── plugins/engine/<engine>/skills/  # engine plugin skills
    └── .agents/          # pipeline-dev internals (lint, sandbox-init)
```

The consumer session reads game-build skills at `.agents/skills/...` and
`.agents/plugins/engine/<engine>/skills/...` — canonical paths, no staging
or symlinks. Pipeline-dev skills stay nested at `.agents/.agents/` (behind).

Why a submodule: the consumer repo's history records **which commit** a
sandbox was built against — reproducible A/B comparison, and the layout
matches how consumers run in production. Why a mirror: git refuses a
submodule URL equal to the superproject, so the script maintains a sibling
bare mirror (`../mythic-quest-mirror.git`), refreshed from HEAD each run.

## Run it

```bash
.agents/skills/sandbox-init/scripts/init.sh <harness> <engine> [sandbox-name]
```

- `harness` (required): any `bd setup` recipe — opencode, codex, claude, ...
  Generates the right instructions file (AGENTS.md, CLAUDE.md, ...).
- `engine` (required): name under `plugins/engine/` — godot today.
- `sandbox-name` defaults to `benchmark`; simple name (no dots/slashes).
- All harnesses read `.agents/` natively — no bridges or symlinks needed.
- Idempotent and **destructive by design**: sandbox content is deleted,
  including any game built by a prior run.
- Refuses to wipe while a live harness session holds the sandbox.
- Exit 0 = verified ready; exit 1 = reason printed, fix before launch.

## After prep — launching the session

1. `cd test/<name>`
2. Start the harness from the sandbox root — skills and governance rules
   are read from `.agents/` natively.

## Gotchas

- **The submodule pins the last COMMITTED HEAD.** Uncommitted changes are
  excluded — commit first. That is the reproducibility point.
- `protocol.file.allow=always` is per-invocation (`git -c`) — global git
  config stays untouched.
- Recipes that install into `.agents/` (e.g. codex's skill) dirty the
  submodule worktree — hidden via checkout-local excludes.
- The mirror is disposable; force-fetch keeps it tracking HEAD.
