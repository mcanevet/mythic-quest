# Sandbox Init

Reset a disposable consumer sandbox to a pristine, verified, launch-ready
state — one deterministic script, not a hand-typed cleanup sequence.

## When to use

- About to start a game-build session in a sandbox
- Previous run died mid-way and the sandbox is dirty
- Suspect a sandbox is broken (drifted submodule, missing ledger)

## Layout the script creates

```
test/<name>/              # fresh consumer git repo (opencode cwd anchor)
├── AGENTS.md             # generated by bd setup opencode (managed Beads block)
├── .beads/               # fresh bd ledger (bd init --quiet --stealth)
└── .agents/              # git SUBMODULE -> harness repo @ committed HEAD
    ├── lint/rules.yaml   # governance rules (single source of truth)
    └── skills/           # lint, sandbox-init, ... skills
```

Why a submodule: the consumer repo's history records **which harness commit**
a sandbox was built against — reproducible A/B comparison across harness
versions, and the layout matches how consumers run in production. Why a
mirror: git refuses a submodule URL equal to the superproject, so the script
maintains a sibling bare mirror (`../mythic-quest-mirror.git`), refreshed
from harness HEAD on every run.

## Run it

```bash
.agents/skills/sandbox-init/scripts/init.sh [sandbox-name]
```

- `sandbox-name` defaults to `benchmark`; must be a simple name (no slashes).
- Sandboxes live under `test/` (gitignored in the harness repo).
- Idempotent and **destructive by design**: any existing content in the
  sandbox is deleted, including a game built by a prior run.
- Refuses to wipe while a live opencode session holds the sandbox (zombie
  contamination guard).
- Exit 0 = verified ready (prints pinned SHA + launch command); exit 1 =
  verification failed — read the printed reason and fix before launch.

## After prep — launching the session

1. `cd test/<name>`
2. Start the harness (opencode or equivalent)
3. The game-build session sees the skills in `.agents/skills/` and the
   governance rules in `.agents/lint/rules.yaml` — the lint-first gate works
   from inside the sandbox.

## Gotchas

- **The submodule pins the last COMMITTED harness HEAD.** Uncommitted harness
  changes are excluded — commit first. That is the point: a sandbox you can
  attribute to a citable SHA.
- `protocol.file.allow=always` is set per-invocation (`git -c`) for the
  `submodule add` — global git config stays untouched.
- The mirror is disposable; force-fetch keeps it tracking HEAD even across
  history rewrites.
